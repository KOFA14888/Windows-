# ЭТАП 1 — Boot & Setup

> Реализовано полностью и запускается одной командой: `dotnet run --project src/Win10Sim.App`.

---

## 1. Поток экранов

```
                    ┌─────────────────────────────┐
                    │ state.json (OsPhase + сессия)│
                    └──────────────┬──────────────┘
                                   │ загрузка/сохранение после каждого шага
┌──────────────┐   ┌───────────────▼──────────────┐
│  Application │──▶│          BootFlow            │
│  (хук Insert)│   │  while(true) { phase → view } │
└──────────────┘   └───────────────┬──────────────┘
                                   │ ScreenManager.ShowAsync (кросс-фейд 140/220 мс)
        ┌──────────────────────────┼──────────────────────────────────────────┐
        ▼                          ▼                                          ▼
 WindowsLogo(3 s)        SetupLanguage ──▶ SetupInstall ──▶ SetupKey ──▶ SetupEdition
        │                                                  │(нет ключа)      │
        │                                                  │(есть ключ)      │
        │                                                  ▼                 ▼
        │                                              SetupEula ──▶ SetupInstallType
        │                                                                  │
        │                                                                  ▼
        │                                                             SetupDisk (формат)
        │                                                                  │
        │                                                                  ▼
        │                                            SetupCopying (0–100 %, ~42 с)
        │                                                                  │
        └──────────────────── Reboot (логотип 5 с) ◀───────────────────────┘
                                   │
                                   ▼
                    OobeWait → (ЭТАП 2) заглушка с итогом
                                   │ «Установить заново» → Firmware → сброс сессии
                                   ▼

```

Каждая стрелка — сохранение `state.json` **до** показа следующего экрана, поэтому
выход по `Insert` в любой момент не теряет прогресс.

## 3. Решения, которые стоит знать

**Состояние — в файле, а не в памяти.** `BootFlow` после каждого экрана пишет
`state.json` (атомарно: `state.json.tmp` → `File.Move(overwrite: true)`). Поэтому
«перезагрузка» — не имитация: процесс можно убить, и установка продолжится с той же
фазы. При повреждённом JSON рядом сохраняется `state.json.corrupted`, а сессия
начинается заново — симулятор никогда не «не запускается».

**Экраны не навигируют.** Экран объявляет `Advance(OsPhase.X)`, а решение и
сохранение делает `BootFlow`. Добавить экран = добавить `case` в `CreateScreen`
и один класс; порядок шагов по-прежнему виден в одном файле.

**Язык установки меняет всю ОС.** Строки в XAML взяты через `{DynamicResource L.*}`;
`LocalizationService` подменяет словарь `Lang.ru.xaml ⇄ Lang.en.xaml` в
`Application.Resources`, WPF перерисовывает всё сам. Плюс меняется
`CultureInfo.DefaultThreadCurrentCulture` — форматирование дат и чисел идёт за языком.

**Ключ проверяется по правилам, а не «на глаз».** Алфавит настоящих ключей
(без `0/O/1/I/L/S/B/8`), 25 символов, пять групп; generic-ключи Windows 10 дают
Home/Pro/Enterprise; остальные корректные ключи получают редакцию детерминированно
(по FNV-хэшу) — один и тот же ключ всегда даёт одну и ту же редакцию, что удобно
и для демонстрации, и для тестов.

**«Далее» на экране диска недоступно до форматирования.** Это не украшение:
настоящий установщик не даёт ставить систему в неотформатированный раздел, и
одновременно это защита от случайного «прощёлкал и затёр диск».

**Никаких `Thread.Sleep`.** Установщик — `async` с `CancellationToken`;
прогресс идёт через `IProgress<T>` (колбэки на UI-потоке). Выход по `Insert`
прерывает установку мгновенно, а не через 20 секунд.

**Скорость установки — одна настройка.** `SetupTimings.SpeedFactor`: `1.0` ≈ 45 с,
`0.2` — быстрый прогон, `3.0` — медленно, чтобы рассмотреть экраны.

## 4. Чек-лист ручной проверки

1. `dotnet run --project src/Win10Sim.App` → чёрный экран, логотип, точки, через ~4 с — язык.
2. Сменить язык на English → **весь** интерфейс (включая заголовки и подписи кнопок)
   переключился мгновенно; вернуть русский.
3. «Далее» → «Установить сейчас» → ввести мусор в поле ключа: буквы `I/O/S/B/L` и цифры
   `0/1` не вводятся, дефисы появляются сами; «Далее» → ошибка «25 символов».
4. Вставить `VK7JG-NPHTM-C97JM-9MPGT-3V66T` → шаг выбора редакции **пропущен**,
   сразу условия лицензии.
5. «Назад» на экран ключа → «У меня нет ключа продукта» → выбор редакции → Enterprise.
6. EULA: флажок серый, пока текст не прокручен до конца; после прокрутки — активен,
   «Далее» включается только с флажком.
7. Тип установки: «Обновление» недоступно, «Выборочная» выбрана.
8. Диск: «Далее» неактивна; выбрать «Раздел 3» → «Форматировать» → оверлей
   «Быстрое форматирование (NTFS)» → «Создание файловой системы…» → статус
   «Раздел отформатирован», «Далее» активна. Выбрать другой раздел → снова неактивна.
9. Копирование: проценты идут 0→100 без скачков назад, подписи этапов меняются
   4 раза, пути файлов появляются; в конце — «Компьютер перезагрузится…».
10. Логотип и точки (~5 с) → экран «ЭТАП 1 завершён» с ключом, редакцией, разделом.
11. **Insert на любом экране** → мгновенный выход на рабочий стол, панель задач на месте.
12. Запустить снова → возврат на ту же фазу (проверьте `%LocalAppData%\Win10Sim\state.json`).
13. «Установить Windows заново» → полный сброс и логотип заново.

## 5. Автоматические проверки

```powershell
dotnet test                                   # xUnit: ключи, состояние, установщик, локализация
python3 tools/check_xaml.py                   # XAML + ресурсы + обработчики (работает без .NET)
python3 tools/check_csharp.py                 # синтаксис C# (tree-sitter), тоже без .NET
```

`check_xaml.py` проверяет то, что обычно ломает сборку WPF, но не видно в диффе:
well-formed XAML, существование каждого `{StaticResource}`/`{DynamicResource}`,
соответствие `x:Class` и code-behind, наличие каждого `Click=`/`SelectionChanged=`
обработчика, паритет ключей `Lang.ru.xaml`/`Lang.en.xaml`, наличие в словарях
всех строк, на которые ссылается C#.

## 6. Что дальше (ЭТАП 2 — OOBE)

Точка расширения — `BootFlow.CreateScreen`: фазы `OobeWait … OobePreparing` уже есть
в `OsPhase` и уже сохраняются в `state.json`, вместо `StageCompleteView` появятся:

* `OobeWaitView` — «Подождите…» / «Just a moment…» с тем же спиннером;
* `OobeRegionView` — выбор региона (список стран, локаль);
* `OobeKeyboardView` — раскладка + вторая раскладка;
* `OobeAccountView` — имя пользователя (валидация, проверка занятости), пароль +
  контрольный вопрос; хэш пароля — PBKDF2 в `Core/Accounts`;
* `OobeHelloView` — «Привет» с анимацией появления;
* `OobePreparingView` — «Мы готовим всё для вас» с этапами;
* дальше — Lock Screen с часами и вводом пароля (ЭТАП 3).
